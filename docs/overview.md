# Chamberlain

Chamberlainは、PC上に常駐して「秘書のように」ユーザーを支援するデスクトップアプリを、開発者が最小限のコードで構築するためのAIエージェントフレームワークです。

## 何を作るためのものか

Chamberlainを使って作るアプリは、次のような性質を持ちます。

- **常駐する** — 起動後はシステムトレイに留まり、ユーザーが明示的に終了するまで動き続ける。
- **ユーザーを知っている** — ユーザーの人物像や日々の活動を継続的に学習し、判断や提案に活かす。
- **自発的に動く** — 明示的な指示を待たず、決められたタイミングや学習した文脈にもとづいて自分から状況を確認し、動く。
- **単一のデスクトップアプリとして配布される** — 最終成果物はTauriで構築されたクロスプラットフォームのデスクトップアプリ（Windows / macOS / Linux）となる。

これは「常時オンラインの、控えめで賢い秘書（chamberlain）」というメタファに沿った設計です。四六時中話しかけてくるチャットボットではなく、必要なときに、必要なことだけを、目立たない形で知らせるアシスタントを想定しています。

## ユーザーとの関わり方

Chamberlainアプリは、ユーザーと次の三つのモードで関わることを想定しています。実際の秘書がそうであるように、それぞれ「気づいたことを知らせる／気を利かせて動く／呼ばれたら応える」に対応します。

- **気づいたことを伝える** — 開発者が定義したタイミングで状況を確認し、必要ならOSのネイティブ通知でさりげなく伝える。「毎朝10:00に今日の予定」「1時間おきにレビュー待ちPRを確認」といった、決まったリズムで動く支援。
- **気を利かせて動く** — 学習したユーザー像や日々の活動から、こちらから動くべきタイミングを判断する。実際にアクションを実行する場合は、必ず提案としてユーザーに提示し、確認をとってから行う。
- **呼びかけに応える** — デスクトップUIには秘書と自然言語で会話できるチャットがあり、ユーザーからいつでも話しかけられる。質問への回答、依頼への対応、進行中の作業の相談などを引き受ける。

## 開発者が書くもの

Chamberlainにおけるアプリ開発の中心は**トリガー**の定義です。開発者は「いつ／何がきっかけで／何を確認して／何を通知するか」を組として書き、Chamberlainのコアに登録します。

想定される例：

- 毎朝10:00に、その日のカレンダー予定を通知する
- 1時間おきに、自分がレビュー担当になっているGitHub PRを確認し、あれば通知する
- 特定のフォルダに新しいファイルが置かれたら、その内容を要約して通知する

コア（常時稼働のスケジューラ、ユーザーの学習、チャットUI、OS通知の配送）はChamberlain側が提供し、開発者はビジネスロジック——「何を見て」「どう判断して」「何を伝えるか」——に集中します。これは、Web開発フレームワークがルーティングやライフサイクルを提供し、アプリケーション固有のロジックを開発者に書かせるのと同じ責務分担です。

## 基本設計

- **成果物はTauriアプリ** — 常駐性・トレイ・OS通知・チャットUIはTauri（Rust＋Web技術）側で実装する。
- **常時稼働のコア＋開発者定義のトリガー**という責務分割 — コアはスケジューラ・ユーザー学習・チャット・OS統合を担い、開発者はトリガー（スケジュールとロジックの組）を登録することでアプリを構築する。
